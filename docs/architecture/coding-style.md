# DSS Universe Coding Style

## Core principle

Every file should answer three questions before the developer reads the code:

1. What is this file?
2. Why does it exist?
3. What should never be done here?

## General rules

- Keep files focused.
- One file = one clear responsibility.
- Avoid hidden magic.
- Prefer explicit architecture over clever shortcuts.
- Internal module imports should be relative.
- Barrel exports are for external usage only.

## DSS rule

Code should be clean.
Headers should explain the mission.
Comments should help the future developer, not decorate chaos.
