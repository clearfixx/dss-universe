# Changelog

All notable changes to DSS Universe will be documented in this file.

The format is based on the principles of **Keep a Changelog** and follows **Semantic Versioning**.

---

# Purpose

The CHANGELOG provides a concise summary of user-visible and developer-relevant changes introduced in each release.

Unlike the Version History, this document focuses on individual changes rather than project milestones.

---

# Categories

Changes should be grouped using the following categories whenever applicable.

## Added

New features.

---

## Changed

Changes to existing functionality.

---

## Deprecated

Features planned for removal.

---

## Removed

Removed functionality.

---

## Fixed

Bug fixes.

---

## Security

Security improvements and vulnerability fixes.

# Writing Guidelines

Entries should:

- describe the change, not the implementation;
- remain concise;
- focus on information useful to developers and users;
- avoid duplicating commit messages.

---

# Philosophy

The CHANGELOG answers one question:

> **What changed in this release?**

For project evolution and historical milestones, refer to:

```text
VERSION_HISTORY.md
```

**Build for years, not for weeks.**
